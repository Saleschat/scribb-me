- Lead with what the reader can do or needs to know. Put the reason before the steps only if it's short.
- Address the reader as "you". Use the imperative for steps: "Run the command", not "You should run the command".
- Use sentence case for headings. Make each heading say what the section covers.
- One action per numbered step. Put the expected result after the step that produces it.
- Don't call things simple, easy or obvious. Remove "just" and "simply".
- Use descriptive link text, never "here" or "click here".
- Format UI elements in bold, and code, commands, paths and values in code font.
- Prefer present tense and active voice. Avoid "will" for things that happen right away.
- Spell out "for example" and "that is" instead of e.g. and i.e.
- Use the Oxford comma. Keep exclamation marks out of docs.
